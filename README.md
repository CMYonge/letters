# Charlotte Mary Yonge Letters Project

A scholarly digital edition of approximately 1,900 letters by Charlotte Mary Yonge (1823–1901), 
converted from a legacy WordPress database into a static website hosted on GitHub Pages.

Live site (demo): https://cmyonge.github.io/demo_letters  
Target domain: charlottemyonge.org.uk (forthcoming)

---

## Repository Structure

The repository contains two main folders. The pipeline folder holds the four R scripts that build the website. The data folder holds the source CSV files which are the canonical data for the project. The root level contains _quarto.yml (Quarto website configuration), styles.css (custom styling), and this README.
---

## Pipeline

The pipeline converts a WordPress SQL dump into a Quarto static website.
It is written in R and consists of four steps. Run them in order.
After running the pipeline, run `quarto render` from the repo root to build the site.

### STEP0 — Extract from SQL dump (`pipeline/STEP0_extract.R`)

Reads the raw WordPress SQL dump (split across multiple `.txt` line files) and extracts:
- Individual letter HTML files, one per letter, named `{post_id}-{slug}.html`
- `wp_posts.csv` — post ID and slug lookup table used by later steps

This step only needs to be rerun if a new or corrected SQL dump is received.
It is increasingly a historical step as the project moves to CSV-based corrections.

### STEP1 — Convert letters to QMD (`pipeline/STEP1_convert_letters.R`)

Reads the extracted HTML letter files and `wp_letterinfo.csv`, and produces
one Quarto markdown (`.qmd`) file per letter with:
- YAML front matter (title, date, location, manuscript reference, post ID)
- Letter body converted from HTML to markdown
- Footnotes extracted and formatted
- Internal entity tags (`[[person:N]]`, `[[cmybook:N]]` etc.) passed through
  for STEP3 to resolve into links

Rerun whenever `wp_letterinfo.csv` is edited or letter formatting is changed.

### STEP2 — Create reference pages (`pipeline/STEP2_reference_pages.R`)

Reads the bibliography and entity CSVs and produces one `.qmd` page per entity:
- People pages (from `persons.csv`)
- Organisation pages (from `wp_others.csv`)
- CMY bibliography pages (from `wp_cmybibliography.csv`)
- General bibliography pages (from `wp_generalbibliography.csv`)

Each page lists the letters that mention that entity.
Rerun whenever entity CSVs are edited or new entities are added.

### STEP3 — Build site and resolve links (`pipeline/STEP3_build_site.R`)

Assembles the full website folder structure and converts internal entity tags
to working relative links. For example `[[person:238]]` becomes a markdown
link to `../people/person_238.html`. Handles all four tag types:
`[[person:N]]`, `[[other:N]]`, `[[cmybook:N]]`, `[[otherbook:N]]`.

Also creates index pages for each section and the decade navigation pages.
Rerun after STEP1 or STEP2, or for any structural or configuration changes.

### When to rerun which steps

| What changed | Steps to rerun |
|---|---|
| `wp_letterinfo.csv` edited | STEP1, STEP3 |
| Bibliography or entity CSV edited | STEP2, STEP3 |
| Letter formatting bug fixed | STEP1, STEP3 |
| New SQL dump received | STEP0, STEP1, STEP3 |
| Website structure or config | STEP3 only |

Always run `quarto render` after the pipeline steps.

## Data Files (`data/`)

These CSVs are the canonical source of truth for the project. Edits should be 
made here and committed to Git so changes are tracked. Do not edit the copies 
in `C:/db/` directly — keep that folder in sync with this one.

### `wp_letterinfo.csv`
One row per letter. Key fields:
- `letterInfo_ID` — unique letter identifier
- `letter_date` — display date as written (may include uncertainty markers such as [n.d.], [n.y.], [c. 1870])
- `letter_dbdate` — structured date in YYYY-MM-DD format for sorting; 00 used for unknown components
- `letter_fromAddress` — address from which the letter was written
- `letter_footnote` — editorial footnotes

### `wp_cmybibliography.csv`
One row per work by Charlotte Mary Yonge. Key fields:
- `cmy_bookID` — unique identifier
- `title` — title as it appears in the source (may use library catalogue inversion, e.g. "Daisy Chain, The")
- `display_title` — title with leading article restored (generated by pipeline)
- `sort_title` — plain text title without leading article, for alphabetical sorting (generated by pipeline)
- `date`, `genre`, `publisher`, `notes`

### `wp_generalbibliography.csv`
One row per work by other authors referenced in the letters.
Fields include `author`, `title`, `date`, `publisher`.

### `wp_others.csv`
One row per organisation, place, topic, or periodical referenced in the letters.
Fields include `name`, `type`, `notes`.

## Tools Required

- **R** with packages: `tidyverse`, `stringr`, `readr`, `data.table`
- **Quarto** (for rendering the website)
- **Git Bash** (for version control)
- **Notepad++** (recommended for editing CSV and markdown files — always use UTF-8 encoding)

Do not edit CSVs in Microsoft Excel — it will corrupt accented characters.

---

## Recommended Editing Tool for Non-Coders

For editing CSV files: **Notepad++**. When opening a file, confirm the encoding 
shown in the bottom status bar reads `UTF-8`. Use LibreOffice Calc or Google Sheets 
for viewing data in column format, but make edits and save in Notepad++.
